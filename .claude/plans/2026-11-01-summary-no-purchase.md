# AI 요약에서 매입 미입력 현장을 마진율에서 분리

- **시작일**: 2026-11-01
- **BACKLOG 항목**: 주 에이전트 위임 작업(대시보드 AI 요약 오해 수정). BACKLOG/PROGRESS/HANDOFF는 주 에이전트가 갱신
- **예상 규모**: S
- **상태**: DONE

## 목표
`GET /api/v1/dashboard/summary`가 매입 0원 현장을 합산해 "매입 0원, 마진율 100.00%", "주의할 현장이 없습니다"라고 쓰지 않게 한다.
매입 미입력 현장을 따로 세고, 마진율은 매입이 입력된 현장만으로 서버가 계산한다.

## 배경 / 동기
과거 견적만 등록하고 매입을 아직 넣지 않은 현장이 대부분이다. 기존 사실 판정(PR #279·#280)은 견적 미등록·수주 전만
평가에서 뺐기 때문에, 견적만 있는 현장이 마진율 100% 정상 현장으로 섞여 전체 마진율을 부풀리고 주의 현장이 없다고 단정했다.

## 접근법
- `DashboardSummaryFacts.from`: 견적 미등록 → 수주 전 → **매입 합계 0 = 매입 미입력** → 손익 평가 순으로 분류.
  - 매입 미입력은 `noPurchaseSites`에 "견적 X원, 매입 미입력"으로 기록하고 평가·주의 판정에서 뺀다.
  - 마진·마진율은 손익 평가 대상(매입 입력 현장)의 견적·매입 합으로 서버가 직접 계산(소수 2자리 HALF_UP). stats 평균 마진율은 쓰지 않는다.
  - 평가 대상이 없고 매입 미입력이 있으면 "매입이 입력된 현장이 없어 마진율을 계산하지 않음".
  - 매입 미입력만 있어 매입 합계가 0이면 합계 줄에 "매입 0원" 대신 "매입 미입력".
  - 다음 할 일: 적자 → 저마진 → "매입 입력 필요(N개)" → 견적 등록.
  - 손익 문장: "매입 미입력 N개 현장은 마진율 계산에서 제외", 주의 현장이 비어도 매입 미입력이 있으면 "주의할 현장이 없습니다" 대신 판단 불가 안내.
- `SummaryOutputGuard`: 매입 미입력 현장이 있을 때 "매입 0원" 또는 "주의할 현장이 없…"을 쓰면 `매입 미입력 오해` 위반. "미입력"을 일반 현장 접두어에 추가. 새 숫자는 기존 사실 목록 대조로 막힌다(마진율 100.00%·stats 평균).
- `OllamaService.SYSTEM_PROMPT`: 매입 미입력 현장 규칙 1문장 추가.
- API DTO(`DashboardSummaryResponse`, `DashboardStatsResponse`)는 변경 없음. `getStats` 집계도 그대로(대시보드 화면 수치는 이번 범위 밖).

## 리스크 / 모르는 것
- 매입이 실제로 0원인 현장(무자재 공사)도 미입력으로 분류된다. 현재 데이터 입력 단계에서는 미입력 쪽이 압도적이라 수용.
- 대시보드 통계 API(`/stats`)의 평균 마진율은 여전히 매입 0원 현장을 포함한다. 화면 수치 정정은 frontend·DTO 영향이 있어 별도 판단.
