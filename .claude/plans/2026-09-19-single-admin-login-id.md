# 단일 관리자 loginId 인증 전환

- **시작일**: 2026-09-19
- **BACKLOG 항목**: P0 — 단일 관리자 loginId 인증 전환
- **예상 규모**: M
- **상태**: DONE (로컬 대화형 관리자 생성 및 인증 후 현장 API 스모크 통과)

## 목표

공개 회원가입을 없애고, 단일 관리자만 `loginId/password`로 로그인하게 한다. 기존 계정과 데이터의 보존 여부를 먼저 확인하고, 새 설치에서는 외부에 열린 가입 API 없이 안전하게 관리자를 만들 수 있어야 완료다. 이번 설치에는 보존할 실사용 데이터가 없었고 새 BuildFlow 볼륨으로 시작했다.

## 배경 / 동기

현재 `POST /api/v1/auth/signup`은 공개되어 있고 요청자가 `ADMIN` 역할을 직접 선택할 수 있다. Gateway는 JWT 서명/만료만 검사하고 access 타입·ADMIN 역할을 강제하지 않는다. 로그인·JWT·프론트·MSW는 이메일을 기준으로 동작한다. 관리자 아이디 전용 화면의 설명과 실제 계약도 일치하지 않는다.

## 접근법

1. 인증 DB를 변경하기 전 기존 계정 여부를 읽기 전용으로 확인한다. 사용자가 실사용 데이터가 없다고 확인했고, Docker 기동 후 기존 BuildFlow 볼륨·계정이 없음을 확인했다. 기존 데이터를 자동 변경·삭제하지 않는다.
2. 사용자가 실사용 DB 데이터는 없고 가족이 관리자 계정 1개를 공유한다고 확정했다. 새 DB에는 관리자 1명만 생성한다. 기존 개발 DB에 계정이 있더라도 자동 삭제하지 않고 별도 백업·정리 절차를 안내한다.
3. 공개 signup 컨트롤러·보안 허용 경로를 제거하고, 인증 서비스 내부에서 단일 관리자 제약을 강제한다. 공개 bootstrap API는 두지 않는다.
4. `loginId`의 유일성/검증, JWT claim, Gateway 검증, 기존 토큰의 무효화·전환 정책을 한 계약으로 맞춘다.
5. `LoginRequest`를 원본으로 프론트 로그인 폼·요청·MSW를 동기화한다. 개발 프록시에서 MSW 비활성화가 실제로 작동하는지도 검증한다.
   로그인 401은 전역 세션 만료 리다이렉트에서 제외해 잘못된 자격증명 오류가 폼에 남도록 한다.
6. `scripts/create-admin.ps1`, README/Windows 가이드, API 명세와 인증 테스트를 새 계약에 맞게 갱신한다.
7. 사용자의 비밀번호를 채팅이나 명령줄에 남기지 않고 정상 로그인과 인증 후 현장 API를 검증할 수 있도록 로컬 대화형 `scripts/verify-admin.ps1`을 제공한다.

## 리스크 / 모르는 것

- 사용자는 실사용 데이터가 없으며 가족이 단일 관리자 계정을 공유한다고 결정했다. Docker Desktop 기동 후 기존 BuildFlow 컨테이너·볼륨이 없고 새 인증 DB의 관리자 계정도 0명임을 확인했다. 자동 삭제·볼륨 초기화는 하지 않았다.
- 초기 관리자 생성은 사용자 결정에 따라 로컬 대화형 PowerShell 명령으로만 제공한다. 웹 설정·가입 API는 두지 않는다.
- 사용자가 9자 비밀번호를 사용한다고 명시해 최초 관리자 비밀번호 최소 길이를 12자에서 9자로 조정했다. 스크립트와 서버가 같은 경계를 검사한다.
- 기존 실데이터 DB에서의 이행은 이번 신규 설치 범위에 포함하지 않는다. 버전 마이그레이션·백업/복구 전략은 P1 백로그로 남겼다. 인증 서비스는 `ddl-auto: validate`와 명시적 `schema.sql`을 사용한다.
- 구 access/refresh 토큰은 `authVersion=2` 검사로 거부한다.
- `create-admin.ps1`은 공개 API 대신 로컬 컨테이너 CLI로 초기화한다.

## 결과 (작업 후 기록)

공개 signup/역할 선택을 제거하고 `admin_accounts`(고정 PK 1)와 로컬 컨테이너 CLI 초기화로 전환했다. JWT `authVersion=2`와 Gateway의 access/ADMIN 검사로 구 토큰을 차단한다. 자동 Discovery Locator 경로는 명시 라우트의 JWT 필터 우회 위험이 있어 비활성화했다. 로그인 폼·MSW·실서버 개발 모드·401 오류 처리도 동기화했다. 인증·Gateway 테스트, 프론트 lint/test/build는 통과했다. Docker Desktop 기동 후 빈 인증 DB 스키마 생성과 관리자 0명, auth/site/gateway health 200, 공개 가입 403, 잘못된 로그인 401, 인증 없는 현장 요청 401, Discovery 자동 경로 404를 확인했다. 관리자 초기화 명령의 빈 입력은 실패(exit 1)하고 계정이 생기지 않았다. 사용자가 직접 입력해 관리자 계정 1개가 생성됐고 DB에는 60자 BCrypt 해시만 저장된 것을 확인했다. `verify-admin.ps1`의 관리자 로그인·현장 API 스모크가 통과했고 임시 현장은 제거됐다. 후속 DB 확인 결과 관리자 1명, 현장 0개, 손익 0건이다.
