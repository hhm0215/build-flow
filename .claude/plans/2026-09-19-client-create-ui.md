# 실사용 UI 라이프사이클 — 거래처 생성

- **시작일**: 2026-09-19
- **BACKLOG 항목**: P0 — 실사용 UI 라이프사이클 연결
- **예상 규모**: S (L 작업의 세 번째 수직 슬라이스)
- **상태**: DONE (UI·MSW 계약 검증, 실서비스 영속 POST는 보류)

## 목표

현장 생성 중 새 거래처를 등록하고 즉시 해당 현장에 연결할 수 있게 한다. 기존 거래처 선택과 거래처 미지정 현장 생성도 유지한다.

## 배경 / 동기

백엔드에는 거래처 POST/GET이 있고 프론트에는 GET 훅만 있다. 새 거래처를 화면에서 만들 수 없어 거래처→현장 실사용 순서가 막혀 있다.

## 접근법

1. 백엔드 `ClientCreateRequest`에 맞춰 `companyName` 필수, 나머지 6개 선택 필드로 프론트 타입·POST mutation을 추가한다. 선택 필드의 실제 `null` 응답도 타입에 반영한다.
2. 현장 생성 모달에서 거래처 등록 모달을 열고, 성공 시 새 거래처를 현장 폼에 자동 선택한다. 실패 시 입력을 유지하고 서버 메시지를 보여준다.
3. MSW POST/GET 거래처 상태를 유지하고 현장 생성 핸들러가 신규 거래처를 찾아 응답하도록 한다.
4. UI 테스트, API/MSW 계약 테스트, lint/build, 정적 검토를 수행한다. 실제 관리자 암호를 수집하지 않는다.

## 리스크 / 모르는 것

- 회사명 외 필드는 서버에서 형식 검증을 하지 않는다. UI는 DB 길이 제한과 이메일 입력 형식을 맞추되 사업자번호 중복 정책은 이번 범위에 넣지 않는다.
- 실제 로그인 상태의 브라우저 E2E는 비밀번호가 필요하다. 사용자 비밀번호를 채팅이나 명령 인수로 받지 않고 모킹·단위 테스트를 먼저 수행한다.

## 테스트 / 검증

- 필수 회사명 공백 차단, 성공 시 생성 ID 자동 선택, 실패 시 재시도, 선택 입력 변환.
- MSW POST 201→GET 목록→현장 POST에 신규 거래처 연결.
- `bun run test`, `bun run lint`, `bun run build`, `git diff --check`.

## 결과 (작업 후 기록)

`ClientCreateRequest`와 POST mutation, 거래처 등록 모달을 추가했다. 현장 생성 중 등록에 성공하면 새 거래처를 즉시 선택하며, 목록 재조회가 늦어도 선택 항목이 유지된다. 서버 오류 시 입력을 보존해 재시도할 수 있다. MSW도 POST 201→GET 목록→현장 POST 응답에 새 거래처를 연결하도록 동기화했다. 읽기 전용 계약 리뷰 결과 선택 필드의 `null` 가능성과 DB 길이를 프론트에 반영했다. 독립 코드 리뷰에서 발견한 현장 생성 중 중복 제출·거래처 모달 경합, 확정 견적과 비동기 손익 집계 경합, 조회 오류 시 금액 오표시를 고치고 회귀 테스트를 추가했다. Vitest 37개·lint·build가 통과했고 프론트 컨테이너를 재빌드해 HTTP 200과 거래처 경로 미인증 401을 확인했다. 거래처에는 삭제 API가 없어 검증 데이터가 남는 실서비스 POST 스모크는 수행하지 않았다.
