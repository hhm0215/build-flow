# 현장 보관·복원 (ADR-021 1차 슬라이스)

- **시작일**: 2026-10-17
- **BACKLOG 항목**: P0 "공개 파일럿 CRUD 실동선 검증·결함 수리" — 현장 삭제 대신 보관
- **예상 규모**: M
- **상태**: DONE

## 목표

현장을 하드 삭제하지 않고 `archivedAt`으로 보관·복원한다. 보관된 현장에는 새 견적·매입·세금계산서·보증을 등록할 수 없고, 과거 자료·손익 조회는 그대로 유지한다.

## 배경 / 동기

현장 DELETE는 PR #89 이후 항상 409라 잘못 만든 현장이나 끝난 현장을 정리할 방법이 없다. 사용자 결정(2026-10-17): 추천안 — site-service `archived_at` nullable 컬럼, 보관 현장 신규 등록 400.

## 접근법

1. site-service: `Site.archivedAt`(nullable), `PATCH /sites/{id}/archive`·`/restore`(행 잠금, 멱등). 응답에 `archivedAt`. 목록 `archived=true|false` 선택 필터(미지정 = 전체, 기존 계약 유지). 보관된 현장의 수정·상태 변경은 409(복원 후 수정).
2. 네 생성 서비스의 `SiteReferenceValidator`: 응답의 `archivedAt`이 있으면 400 `SITE_ARCHIVED`.
3. 프론트: 타입·API 훅·MSW 동기화, 현장 목록 기본 "진행(미보관)" 필터와 보관 보기, 상세 화면 보관/복원 버튼과 보관 배지.

## 리스크 / 모르는 것

- 스키마: site-service는 아직 `ddl-auto: update`. nullable 컬럼 추가라 기존 행은 NULL(미보관)이고 구 이미지도 무시하므로 롤백 호환. 다만 ADR-021은 운영 DB 반영 전 버전 관리형 마이그레이션·복구 게이트를 요구하므로 **VPS/운영 적용은 그 게이트 이후**로 둔다(main 병합 자체가 PR #99 draft로 막혀 있음).
- 경합: 생성 검증 직후 현장이 보관되면 그 1건은 보관 현장에 붙을 수 있다(조회 시점 검증). 보관은 되돌릴 수 있고 자료 손실이 없으므로 이번 범위에서 허용하고, 하드 삭제 전 쓰기 장벽은 별도 항목으로 유지한다.
- 기존 문서 수정 경계(보관 현장 소속 견적 수정 등)는 이번 범위 밖.
