# 계획 문서 (plans/)

작업 시작 전 작성하는 **계획 문서**의 모음.

## 언제 만드는가

BACKLOG.md에서 작업 1건을 선택해 시작할 때, 구현 들어가기 전에 작성.
산출물·접근법·리스크를 미리 정리해서 사용자와 합의한 뒤 코딩을 시작한다.

## 파일명 규칙

`YYYY-MM-DD-{kebab-slug}.md`

예: `2026-06-11-warranty-ocr-scheduler.md`

## 템플릿

```markdown
# {작업 제목}

- **시작일**: YYYY-MM-DD
- **BACKLOG 항목**: BACKLOG.md의 어느 항목인지
- **예상 규모**: S/M/L
- **상태**: PLANNING / IN_PROGRESS / DONE / ABORTED

## 목표
한두 줄로 무엇을 만드는가, 무엇이 끝나면 완료인가.

## 배경 / 동기
왜 지금 이걸 하는가. 무엇이 문제이고 어떤 가치를 만드는가.

## 접근법
구체적 구현 전략. 핵심 결정사항.

## 산출물 체크리스트
- [ ] ...
- [ ] ...

## 리스크 / 모르는 것
사전에 짚고 가야 할 위험. 결정이 필요한 지점.

## 테스트 / 검증
무엇으로 "끝났다"를 확인하는가.

## 결과 (작업 후 기록)
실제로 만든 것, 빠진 것, 다음으로 미룬 것.
실패/예상과 다른 점이 있으면 RETROSPECTIVE.md에 회고 작성.
```

## 완료 후

- 계획 문서 마지막 "결과" 섹션 채움
- BACKLOG.md에서 해당 항목 제거
- PROGRESS.md "완료된 작업"에 한 줄 추가
- 실패/허비가 있었으면 RETROSPECTIVE.md에 회고 추가
