# 하자보증보험 OCR 실패 보정·수정 동선

- **시작일**: 2026-09-20
- **BACKLOG 항목**: P0 실사용 UI 라이프사이클 연결
- **예상 규모**: M
- **상태**: DONE

## 목표
OCR 실패 또는 부분 추출된 보증보험을 화면에서 직접 보정하고, 기존 수기 등록분도 수정할 수 있게 한다. 보정 후 목록·만료 예정 건수가 즉시 새로고침되고 실패 배지가 정상 상태로 바뀌어야 한다.

## 배경 / 동기
현재 목록에는 삭제만 있고 `PUT /api/v1/warranties/{id}` 훅은 화면에서 사용하지 않는다. OCR 실패 레코드의 필드가 비어 있어도 사용자가 이를 고칠 수 없다. 백엔드 `update`도 `ocrStatus`를 그대로 두므로 수동 보정 후 실패 배지가 남는다.

## 접근법
- 기존 PUT 계약을 사용한다. `siteId`는 수정하지 않고 보험사·시작일·종료일 필수, 증권번호·보증금액·메모는 `null` 전송 시 지우는 3-state 의미를 따른다.
- PENDING 행은 OCR 완료 전 수정하지 못하게 UI와 API에서 막아 비동기 결과가 수동 입력을 덮지 않게 한다. 완료된 OCR·수기 레코드의 수정 후 상태는 `MANUAL`로 바꾼다.
- 목록의 행별 수정 모달에서 현재 값을 미리 채우고 오류·중복 저장·날짜 역전·재시도를 처리한다. 만료일 변경 시 목록과 만료 예정 쿼리를 모두 무효화한다.
- MSW PUT 계약과 프론트·백엔드 회귀 테스트를 추가한다.

## 리스크 / 모르는 것
- OCR `SUCCESS`는 일부 필드만 추출해도 부여된다. 필수값이 비어 있으면 수정 폼에서 사용자 입력을 요구한다.
- OCR 비동기 완료와 수정의 경합은 PENDING 상태를 서버에서도 409로 막는다. 완료 후 재조회하여 수정하도록 안내한다.
- 손익 Kafka 경로와 무관한 작은 UI 단계다. 매입 UI와 Kafka 신뢰성 보강의 선후 결정은 별도 유지한다.

## 테스트 / 검증
- Java entity/service 테스트: 수동 전환, PENDING 수정 거부, 3-state 유지.
- Vitest: PUT 직렬화, 기존 값 채움, 필수·날짜 검증, 오류 후 재시도, 중복 저장, PENDING 버튼 비노출, 쿼리 무효화.

## 결과 (작업 후 기록)
목록에서 PENDING을 제외한 보험의 수정 모달을 열어 OCR 실패·부분 추출값을 보정한다. PUT은 siteId/filePath를 건드리지 않고 선택 필드의 `null` 삭제를 보존한다. PENDING은 서버 409, 보정 완료는 `MANUAL`; 날짜 역전과 음수 금액은 서버 400으로 차단한다. OCR 응답의 nullable 날짜·보험사·증권번호를 프론트 타입/목록/현장 상세/MSW에 반영했다. 독립 리뷰 MEDIUM 3건(서버 기간 검증, 종료일 없는 유효 필터, MSW 만료 임박) 수정·재검토 완료. 전체 Gradle 테스트, 프론트 65개 테스트·lint·build 통과. Docker 프론트·notification health/목록 GET 200과 Gateway 미인증 API 401 확인. 실제 PDF 업로드와 영속 PUT 스모크는 수행하지 않았다. PR #52는 CI 6개 성공·2개 커밋 SHA 일치 후 merge commit `af4ad46`으로 병합됐다.
