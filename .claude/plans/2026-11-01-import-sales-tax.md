# 홈택스 매출 세금계산서 가져오기

- **시작일**: 2026-11-01
- **BACKLOG 항목**: 로컬 실데이터 적재(USB) 후속 — 견적 가져오기 도구에 매출 세금계산서 추가
- **예상 규모**: M
- **상태**: DONE

## 목표
홈택스 '매출전자세금계산서목록'(.xls/.xlsx)을 견적 가져오기와 같은 흐름(미리보기 → `--emit-plan` → 로그인 페이지에서
`browser_apply.js` → `--record-result`)으로 tax-service `POST /api/v1/taxes`(type `SALES`)에 넣는다.

## 배경 / 동기
견적은 로컬에 적재했지만 매출 세금계산서가 없으면 미수금·현장 손익 검증이 비어 있다. 홈택스 목록은 현장 정보가 없어
계획 시점에 현장을 정할 수 없으므로, 적용 시점에 현재 DB 거래처·현장 목록으로 보수적으로 연결한다.

## 접근법
- `scripts/import/tax_sheet.py`: 머리글 행을 글자(작성일자·상호·공급가액 필수)로 찾고 열을 머리글 글자로 매핑.
  세액 열이 없는 예전 내보내기는 세액 = 합계금액 − 공급가액. 상단 요약 '총 공급가액'(+총 세액·총 합계금액)과
  행 합계가 다르면 ERROR. 금액은 소수 2자리·정수 13자리(서버 `@Digits(13,2)`·`DECIMAL(15,2)`), 합계 ≠ 공급+세액은 ERROR,
  세액 ≠ 공급가액 10%(±1원)는 경고만.
- `scripts/import/taxes.py`: 미리보기·`--emit-plan`·`--record-result`. 계획에는 행 정보와 출처 표식
  `[가져오기 매출 sha256:<16자> 행:<n>]`만 담는다(현장 미정). 같은 바이트 사본·기간이 겹친 내보내기의 같은 내용 행은
  앞 파일 것만 쓴다(같은 파일 안의 같은 행은 서로 다른 계산서일 수 있어 유지). 음수(수정) 세금계산서는 API가 받지 않으므로
  "확인 필요"로 막고 `--skip-negative`로만 빼고 진행. 직접 `--apply`는 두지 않는다.
- `browser_apply.js` `buildflowApplyTaxPlan`: 상호 정규화(주식회사·(주)·㈜·공백·기호 제거) 일치 활성 거래처 1곳 +
  그 거래처 활성 현장 중 현장명 키가 품목명 키에 포함되는 현장 정확히 1개일 때만 생성. 0개·여럿은 skipped에
  사유(거래처 없음/현장 없음/후보 여럿 + 후보 ID). 메모 표식이 있으면 연결만(재실행 안전), 다른 파일·수동 입력으로 같은
  작성일자·상호·공급가액·세액이 있으면 건너뜀. 거래처·현장 생성과 입금 확인은 하지 않는다.
- ledger kind `tax`, 키 (대상, sha256, 행). `estimates.py --record-result`도 세금계산서 결과 형식을 받아 위임.

## 리스크 / 모르는 것
- 품목명에 현장명이 없거나 거래처가 DB에 없으면 연결되지 않는다 — 결과의 사유로 사용자가 정리 후 다시 계획.
- 수정(음수) 세금계산서는 현재 API 범위 밖. 빼고 넣으면 해당 원 건만큼 매출이 크게 잡히므로 화면에서 상계 필요.
- 매입 세금계산서는 설계 결정 대기로 범위 밖.
