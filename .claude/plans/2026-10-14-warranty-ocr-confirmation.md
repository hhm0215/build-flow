# 보증보험 OCR 추출값 확인·만료 알림 안전장치

- **시작일**: 2026-10-14
- **BACKLOG 항목**: 공개 파일럿 CRUD 실동선 검증·결함 수리 — OCR 후속 검증
- **예상 규모**: M
- **상태**: IN_PROGRESS (로컬 검증 완료, PR·공개 파일럿 검증 대기)

## 목표

OCR이 일부 필드만 추출했거나, 모든 필드를 추출했지만 사용자가 확인하지 않은 보증보험을 확정 만료 사실/자동 알림으로 취급하지 않는다.

## 배경 / 동기

기존 구현은 필드 하나만 추출해도 `SUCCESS`였고 종료일 하나만 있으면 유효·만료와 D-day를 표시했다. OCR 추출 정확성은 사용자 확정의 증거가 아니다.

## 접근법

- 필수 보험사·시작일·종료일과 유효 기간을 모두 추출했을 때만 `SUCCESS`로 표시한다. 미완전 결과는 `FAILED`지만 추출값은 보정용으로 남긴다.
- `SUCCESS`도 확인 전 상태로 유지한다. 사용자 수정/확인 저장 후 `MANUAL`만 만료 목록·알림 대상이 되며, 발행 직전 잠금 후 재검증한다.
- 응답에 `expiryConfirmed`를 추가하고 화면의 미확정 만료 문구·필터를 차단한다. 원본 열람/감사 이력은 별도 실데이터 게이트로 남긴다.

## 리스크 / 모르는 것

- 현재 PC Docker Engine 미기동으로 localhost Compose 통합 검증은 불가하다.
- 기존 미발행 outbox 이벤트는 새 자격 검사 없이 전송될 수 있다. 실데이터 전 큐 감사가 필요하다.
- KST 스케줄러와 시스템 기본 시간대의 조회/응답 날짜 경계가 다르다. 자정 회귀가 필요하다.
- 앱 내 PDF 원본 확인 경로와 확정 감사 이력이 없다. 이번 조치는 알림의 보수적 안전장치이며 실데이터 운영 승인 근거가 아니다.

## 테스트 / 검증

`./gradlew test`, `bun run lint`, `bun run test`, `bun run build`, `git diff --check`; 이후 PR CI/SHA 검증. VPS는 합성 PDF만 사용하고 배포 게이트를 별도로 적용한다.
