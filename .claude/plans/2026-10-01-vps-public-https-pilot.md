# VPS 외부 HTTPS 테스트 접속

- **시작일**: 2026-10-01
- **BACKLOG 항목**: VPS 외부 HTTPS 테스트 접속
- **예상 규모**: M
- **상태**: IN_PROGRESS

## 목표

기존 15개 앱·인프라 포트를 loopback에 유지하고, VPS 기본 호스트명에서 HTTPS 프록시를 통해 테스트 데이터만 외부에서 확인한다. 실제 호스트명은 Git 제외 운영 기록으로 관리한다. 인증서 또는 보안 검증이 실패하면 공개하지 않는다.

## 배경 / 동기

사용자는 Tailscale 설치 대신 일반 브라우저의 공개 HTTPS 주소를 원한다. 자체 도메인은 아직 없으며 VPS 기본 호스트명이 공인 IP를 가리킨다. 실데이터용 DB 마이그레이션·외부 백업/격리 복원은 완료되지 않았으므로 공개 파일럿과 운영 승격을 혼동하지 않는다.

## 접근법

1. 공식 Caddy 이미지와 별도 Compose override로 80/443만 공개한다. Caddy는 자동 인증서와 80→443 리다이렉트를 맡고 내부 `frontend:80`으로만 프록시한다.
2. Gateway CORS에는 HTTPS 호스트와 기존 SSH 터널 주소만 허용한다. 기존 서비스의 published port는 그대로 `127.0.0.1`이다.
3. 로그인 API에 보수적인 요청 제한을 적용한다. 공인 접속 검증에는 401/429·로그인·사이트 API 동선을 포함하고, 비밀값은 출력하지 않는다.
4. 서버 변경 전 현재 설정/상태를 기록하고 새 이미지·프록시만 추가한다. 인증서 발급/헬스/포트 검증 실패 시 공개 프록시를 내리고 기존 SSH 터널을 유지한다. 컨테이너/DB 볼륨은 제거하지 않는다.
5. 기본 호스트명에 공인 인증서 발급이 불가하면 무효 인증서 경고를 우회하지 않고 사용자 소유 도메인을 요청한다.

## 리스크 / 모르는 것

- Hostinger 기본 호스트명의 ACME 인증서 발급 가능 여부는 실측 전 미확정.
- 2 vCPU/8 GiB에서 추가 프록시의 자원 여유를 측정한다.
- 기본 관리자 로그인만으로 공개하면 무차별 로그인 시도가 가능하므로 요청 제한을 선행한다.
- 공개 URL은 테스트용이다. 실제 업무 데이터 투입은 DB 마이그레이션·DB/파일 외부 백업·격리 복원 뒤로 유지한다.

## 테스트 / 검증

- Caddy 설정 검증, Compose config에서 비loopback published port가 80/443만인지 검사
- 기존 15개 서비스 헬스·SSH 터널 200/401 유지, HTTPS 인증서 신뢰·80→443·로그인/API/로그아웃 확인
- 로그인 제한 단위/런타임 검사 및 리버스 프록시 헤더/CORS 거부 검사
- 실패 시 공개 프록시 중단 후 기존 터널 접속 재확인

설정과 런북은 작성했다. 로컬 프론트 lint·33파일 112테스트·빌드, Python 검증기 5테스트, Compose 병합·포트 검사를 통과했다. 독립 리뷰의 서버 stale checkout 지적을 반영해 릴리스 SHA 고정을 추가했다. PR #68의 CI 8개(이미지 기반 Caddy/Nginx 구문 포함)가 통과해 `main`에 병합했고 `develop`도 동기화했다. VPS 공인 인증서/접속 검증은 사용자 공개 확인을 기다리며, 실데이터 운영 승격은 범위 밖이다.
