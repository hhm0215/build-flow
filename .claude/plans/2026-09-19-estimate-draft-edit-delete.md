# 실사용 UI 라이프사이클 — 작성 중 견적 수정·삭제

- **시작일**: 2026-09-19
- **BACKLOG 항목**: P0 — 실사용 UI 라이프사이클 연결
- **예상 규모**: M (L 작업의 다섯 번째 수직 슬라이스)
- **상태**: DONE

## 목표

작성 중(DRAFT) 견적의 제목·날짜·메모·항목을 수정하고 삭제할 수 있게 한다. 확정본의 삭제 정책은 문서와 백엔드가 충돌하여 사용자 결정을 기다리는 동안 UI에서 허용하지 않는다.

## 배경 / 동기

백엔드 PUT/DELETE와 프론트 mutation은 있지만 화면에 수정·삭제 진입점이 없다. 현재 DRAFT 입력 오류를 고칠 수 없어 실사용이 막힌다.

## 접근법

1. 백엔드 `EstimateUpdateRequest` 계약(현장 변경 불가, 제목·날짜·항목 필수, 단위 필수)에 맞춘 타입·수정 모달을 추가한다.
2. 목록의 DRAFT 행에만 수정·삭제 버튼을 둔다. 삭제 확인 모달은 중복 요청·닫기 경합을 막고 오류 시 재시도한다.
3. MSW PUT/DELETE가 실제 백엔드의 404·확정 수정 거부와 목록 갱신을 반영하도록 맞춘다.
4. UI/MSW 계약 테스트, lint/build, 독립 코드 리뷰, PR CI·SHA 검증 후 merge한다. 리뷰에서 드러난 금액 정밀도와 수정·확정 경합은 서버 검증·행 잠금으로 같은 슬라이스에서 보강한다.

## 리스크 / 모르는 것

- 문서는 확정 후 수정·삭제 불가지만 백엔드 DELETE는 확정본 삭제 이벤트를 발행한다. 사용자에게 정책 질문을 보냈다. 이 슬라이스는 DRAFT만 대상으로 하므로 응답 없이 진행 가능하다.
- 실사용 견적 데이터 변경·삭제 스모크는 수행하지 않는다.

## 테스트 / 검증

DRAFT만 처리 버튼 노출, 기존 항목 사전 채움, 항목 필수·수량/단가 검증, PUT/DELETE 성공과 오류·중복 요청, MSW 상태를 검증한다.

## 결과 (작업 후 기록)

작성 중 견적의 수정·삭제 버튼과 모달을 연결했다. 수정 시 현장 ID를 보내지 않고 제목·날짜·메모·항목 전체를 PUT하며, 항목 0개·중복 요청·진행 중 닫기를 막고 서버 오류 후 재시도할 수 있다. MSW PUT/DELETE의 404·409·금액 정밀도 응답을 백엔드에 맞췄다. 독립 코드 리뷰에서 소수 정밀도와 수정·확정 동시성 P1을 발견하여 프론트/서버의 반올림 없는 금액 검증과 서버 비관적 행 잠금을 추가했다. 전체 Gradle 테스트, 프론트 Vitest 55개·lint·build 통과, 재검토에서 HIGH/P1 잔여 0건. 견적/프론트 컨테이너 재빌드 후 프론트 200·견적 health 200·미인증 견적 API 401을 확인했다. 실사용 견적 변경·삭제 스모크는 수행하지 않았다. 확정본 삭제 정책은 사용자 답변 대기 중이다. PR #51은 CI 6개 성공·2개 커밋 SHA 일치 후 merge commit `3429a88`로 병합됐다.
