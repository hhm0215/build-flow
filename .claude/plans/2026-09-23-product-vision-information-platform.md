## 목표

BuildFlow를 건설 현장 관리에서 출발해 다양한 사람과 조직의 서로 다른 정보 구조를 수용하는 정보관리 플랫폼으로 발전시키는 장기 방향을 정의한다. 현재 구현 범위와 미래 플랫폼 비전을 구분하고, 이후 작업이 범용성 명목으로 실사용 완성을 방해하지 않도록 단계와 경계를 명시한다.

## 배경 / 동기

USB 견적 자료를 검토하면서 같은 파일명과 날짜만으로 수정본·추가공사·다른 현장을 안전하게 구분할 수 없음을 확인했다. 이 문제는 건설업에만 국한되지 않고, 개인과 조직마다 다른 폴더·파일명·문서 양식과 암묵적 규칙 때문에 발생한다. 사용자는 원본 보존, 유연한 정리, 확정 사례에서 배우는 AI Assistant를 장기 제품 목적으로 요청했다.

## 접근법

- 범용 정보 코어 후보, 도메인 팩, Assistant의 세 계층으로 제품 경계를 정의한다.
- 원본 불변성, 출처·계보, 버전·관계, 확장 스키마, 감사·데이터 이동성을 핵심 원칙으로 둔다.
- 현재 건설 실사용을 Stage 0으로 유지하고 실제 검증 뒤 공통 코어를 추출한다.
- 실행 가능한 첫 단계만 P1 백로그에 등록하고 후속 단계는 비전 문서의 로드맵으로 관리한다.
- README·기획·ADR·개발 가이드가 같은 방향을 가리키도록 동기화한다.

## 리스크 / 모르는 것

- 범용 플랫폼을 먼저 만들면 현재 실사용 일정이 지연될 수 있다.
- 유연한 메타데이터를 무제한 허용하면 검색·검증·마이그레이션이 어려워질 수 있다.
- 멀티테넌시, 객체 저장소, 벡터 검색을 지금 확정하면 검증되지 않은 운영 복잡도가 증가한다.
- 따라서 Stage 1 전에는 구체 기술이나 신규 서비스 경계를 확정하지 않는다.

## 결과 (작업 후 기록)

제품을 `범용 정보 코어 후보 + 도메인 팩 + 근거 기반 Assistant`로 진화시키는 장기 구조를 정의했다. 원본 불변성, 출처·계보, 버전·관계, 확장 메타데이터, 감사, 데이터 이동성을 공통 원칙으로 확정하고 현재 건설 기능은 첫 번째 도메인 팩으로 유지했다.

실행 범위는 현재 P0를 그대로 우선하고, P1에 문서 코어 Stage 1을 등록했다. Stage 1은 로컬 설정으로 지정한 읽기 전용 소스의 `견적서/2026` `.xlsx`부터 원본 보존·체크섬·관계 검토·손익 반영 버전 분리를 검증한다. 독립 검토 피드백을 반영해 실제 업체명·절대경로는 추적 문서에서 제거하고, 원본 바이트/출처/가져오기 관찰/추출 이력 경계와 보안·복구 합격 기준을 보강했다. 객체 저장소, 벡터 DB, 멀티테넌시, 플러그인 규격은 근거 부족으로 의도적으로 확정하지 않았다.

## 독립 검토 피드백과 처리

| 역할 | 주요 피드백 | 처리 |
|------|-------------|------|
| 제품 전략 | 검증 전 범용 코어 확정 표현, 원본 불변/삭제 충돌, 사례 재사용의 테넌트 경계 부재 | `코어 후보` 승격 조건, 파기 증적, 워크스페이스 내부 학습·정정 전파 원칙 추가 |
| 데이터 보존·아키텍처 | 체크섬과 출처 혼합, 회계 유효 버전 불변식, 복구 합격 기준 부재 | Blob/Source/Observation/ExtractionRun 분리, 작업별 유효 버전 1개, manifest 기반 빈 환경 복원 기준 추가 |
| 변경·운영 감사 | 실제 업체명·절대경로 노출, Stage 1을 현재 기능처럼 서술, 가져오기 보안 기준과 문서 정합성 누락 | 추적 문서에서 경로 제거, 미래형으로 정정, 파서·경로·로그·ACL 위협 기준 및 stale AGENTS 목록 정리 |

재검토에서 남은 실행 경계도 보완했다. Stage 1 목표 ERD에 Blob/Source/Observation/ExtractionRun과 EstimateWork/Revision의 cardinality를 명시하고, 미확정 작업은 회계 유효 버전 0개·확정 후에도 최대 1개만 허용한다. 백업은 완료된 배치 checkpoint에서 DB와 Blob을 함께 고정하고, 내부 `storageKey`와 휴대용 `packageRelativePath`를 분리한다. 성공 기준은 플랫폼이 원본에 수행한 변경 0건과 외부 변경 감지 후 성공 처리 0건으로 나눴다.
