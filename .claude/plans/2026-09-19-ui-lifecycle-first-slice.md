# 실사용 UI 라이프사이클 — 현장 생성 첫 단계

- **시작일**: 2026-09-19
- **BACKLOG 항목**: P0 — 실사용 UI 라이프사이클 연결
- **예상 규모**: S (L 작업의 첫 수직 슬라이스)
- **상태**: DONE (현장 생성 첫 단계 구현 및 인증 후 API 스모크 통과)

## 목표

현재 아무 동작이 없는 ‘현장 추가’ 버튼에서 백엔드 `POST /api/v1/sites` 계약에 맞는 현장을 만들고 목록에서 확인할 수 있게 한다. 고객 생성·견적 확정·수정/삭제는 후속 단계로 남긴다.

## 접근법

1. 이미 존재하는 `useCreateSite` mutation을 재사용한다.
2. 현장명 필수, 거래처 선택·주소·시작/종료일·메모 선택 입력 폼을 만든다. 등록된 거래처가 아직 없으면 거래처 없이 생성 가능하다.
3. 성공 시 목록 캐시를 무효화하고 모달을 닫으며 새 현장 상세로 이동한다. 실패 시 폼을 유지하고 오류를 보여준다.
4. MSW 생성 핸들러가 같은 요청/응답을 사용하도록 보정하고 UI 테스트, lint, build를 실행한다.

## 리스크 / 검증

- Docker 기동 후 현장 서비스 health 200과 인증 없는 요청 401을 확인했다. 대화형 관리자 로그인·현장 생성/조회/삭제 API 스모크가 통과했고 DB에 임시 현장·손익 데이터가 남지 않았다. 브라우저에서 폼을 직접 클릭하는 수동 E2E는 별도로 수행하지 않았다.
- 거래처 생성 화면이 없으므로 이 단계만으로 완전한 실사용 라이프사이클은 아니다. BACKLOG P0는 열린 상태로 유지한다.

## 결과

현장 추가 모달에서 현장명, 선택적 거래처·주소·기간·메모를 받아 기존 생성 mutation으로 전송한다. 성공 시 새 현장 상세로 이동하고, 실패 시 입력을 유지하며 오류를 표시한다. MSW 거래처 조회·현장 생성 응답을 동기화했다. UI 테스트 4개를 포함해 프론트 20개 테스트, lint, build가 통과했다. 관리자 로그인·현장 생성/조회/삭제 API 스모크도 통과했고 임시 현장은 제거됐다. 거래처 생성 등 전체 라이프사이클은 P0 백로그에 남는다.
