# BuildFlow 회고

> 실패/사고/허비된 시간을 기록하고, **재발 방지 규칙으로 변환**하는 문서.
>
> 회고 1건 작성 시 의무 항목:
> 1. **무엇이 일어났는지** (사실)
> 2. **원인** (왜 일어났는지)
> 3. **재발 방지 규칙** (구체적 행동 변경)
> 4. **반영 위치** (CLAUDE.md / 메모리 / hooks / 어디에 규칙을 박았는지)
>
> 4번이 누락되면 회고가 아니라 단순 메모. 반드시 어딘가에 가드레일을 박을 것.

## 2026-06-10 — PR #19, push 누락 상태로 머지

**무엇이 일어났는지**:
- PR #19를 GitHub UI에서 생성 → 머지함
- 그런데 `head=develop=fbae555` 시점이었고, 정작 이번 세션 작업 커밋(공내역서 업로드 UI 3개)은 push 안 된 로컬에 있었음
- 결과: 의도한 변경분이 PR에 안 들어간 채 머지됨

**원인**:
- GitHub UI는 develop이 main보다 앞서 있으면 PR 생성을 허용 — push 잊은 채로 PR 만들면 의도와 다른 변경분이 머지됨
- 사용자가 PR Commits 탭을 확인하지 않고 Create

**재발 방지 규칙**:
- PR 생성 화면에서 **Commits 탭의 커밋 목록을 반드시 확인**한 뒤 Create
- 사용자가 PR 만들기 직전, Claude는 "현재 origin/develop이 의도한 커밋까지 포함하고 있는지" 확인 후 PR URL 제시
- `git fetch` → `git log origin/develop..HEAD`로 미푸시 커밋 검증을 PR 생성 전 절차로 만듦

**반영 위치**:
- `~/.claude/projects/.../memory/feedback_pr_creation.md` — "PR 생성 가드레일 (push 검증 + Commits 탭 확인)"
- 다음 단계로 `CLAUDE.md`에도 PR 생성 절차 명문화 검토

- 사용자가 큰 그림(개발 자동 워크플로우)을 만들고 싶은데, Claude는 매 단계(워킹트리 정리, 커밋 분리 방식 등)마다 A/B/C 옵션을 제시하며 확인 받음
- 사용자가 "지금 뭐가 걸린 거야?" "답답하다"고 표현할 때까지 큰 그림을 못 잡음

**원인**:
- "git 작업 사전 승인" 규칙을 과도하게 적용해서 docs-only 변경에도 옵션을 묻기 시작

**재발 방지 규칙**:
- 사용자가 "워크플로우/시스템/큰 그림"을 언급하면, 단편 확인은 줄이고 한 번에 통합 제안 후 OK/조정 받기
- 옵션을 4개 이상 쪼개고 있다면 그 자체가 신호 — 한 발 물러서서 큰 그림 다시 묻기
- docs-only 변경(파일 추가/규칙 추가)은 사전 승인 없이 진행, 결과만 보고

**반영 위치**:
- 이 회고 자체. 향후 메모리 `feedback_workflow.md`에도 짧게 반영 검토

## 2026-06-10 — PR 생성 자동화 도입 (사고 아닌 의사결정 회고)

**무엇이 일어났는지**:
- 첫 시범 사이클 완주 직후, 사용자가 "PR 머지도 자동화 가능한가?" 질문
- 기존 정책은 "gh CLI 사용 금지" (PR #19 사고 가드레일에서 비롯)
- Plan 모드에서 옵션을 검토한 결과 **PR 생성만 자동, 머지는 사용자 책임 유지**로 결정
- main 브랜치 보호 룰 신설 (PR 경로 강제 + force/delete 금지, approval 0)

**왜 자동화했는가**:
- PR 생성 자체는 반복 작업이라 자동화 가치 큼
- PR #19 사고의 본질은 "push 누락 + Commits 탭 미확인"인데, 이걸 **자동화 안에 체크리스트로 박는 게 사용자가 매번 수동으로 검증하는 것보다 안전**

**어떤 위험을 어떻게 막았는가**:
- 위험: Claude가 실수로 머지 → `gh pr merge` deny 룰 + main 보호 룰 이중 차단
- 위험: 의도 안 한 커밋이 PR에 포함 → 워크플로우 6단계의 `git fetch` + push 누락 검증 체크리스트 의무화
- 위험: 자동화 범위가 시간이 지나며 슬금슬금 머지까지 확장 → 이 회고 자체가 미래의 본인에게 "왜 머지 자동화는 하지 않았는지" 근거 제공

**향후 경계**:
- 자동 머지로 확장하려는 유혹이 생기면 이 회고 + PR #19 사고를 다시 읽을 것
- 자동 머지를 도입한다면 최소 다음 3개가 선행되어야 함:
  - CI 통과 필수 (현재 없음)
  - PR description에 "어떤 BACKLOG 항목인지" 머신 리더블 메타 강제
  - 자동 머지 후 PROGRESS.md 갱신·검증까지 풀 사이클이 멱등하게 동작

**반영 위치**:
- `.claude/settings.local.json` — gh PR 생성/조회 allow, 머지/클로즈/force-push deny
- `CLAUDE.md` "## Git" — PR 생성 가능·머지 금지로 갱신
- `CLAUDE.md` "## 개발 워크플로우" — 6단계 PR 생성 + push 누락 검증 체크리스트 추가
- GitHub main 브랜치 보호 룰 (force/delete 금지 + PR 필수, approval 0)
