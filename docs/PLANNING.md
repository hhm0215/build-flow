# BuildFlow 기획서 v1.0

## 1. 프로젝트 정의

### 1.1 한 줄 요약
건설·시공 소규모 업체를 위한 현장별 문서 통합 관리 + AI 챗봇 플랫폼

### 1.2 배경
아버지 회사(건설 용접업)의 실제 업무를 디지털화.
현재 모든 문서가 엑셀/PDF/카톡으로 분산되어 있어서
현장별 수익이 얼마인지, 미수금이 얼마인지, 문서가 어디 있는지
한눈에 파악이 안 되는 상황.

### 1.3 사용자
- 혜민 (ADMIN): 문서 업로드, 데이터 입력, 전체 관리
- 아버지 (VIEWER): 대시보드 확인, 현장 정보 열람

### 1.4 목적
- 실사용: 집에서 아버지 회사 업무를 처리할 때 사용하는 도구
- 포트폴리오: MSA + 대용량 트래픽 기술스택을 보여주는 백엔드 프로젝트

## 2. 핵심 개념: 현장 중심 문서 관리

### 2.1 현장 = 모든 것의 중심

한 현장에 아래 4종의 문서가 묶여서 관리된다.
문서는 사용자가 직접 파일로 업로드하거나 수동 입력한다.
AI가 문서를 자동 생성하는 기능은 없다.

```
┌─────────────────────────────────────────┐
│              현장 (Site)                 │
│  현장명: 강남 리모델링                     │
│  발주처: ○○건설                          │
│  공사기간: 2026.01 ~ 2026.06             │
│                                         │
│  ├─ 공내역서 (엑셀 파일 업로드)            │
│  │   → 발주처에서 카톡/이메일로 받은 원본    │
│  │                                      │
│  ├─ 견적서 (엑셀 파일 업로드)              │
│  │   → 우리가 직접 단가를 정해서 작성한 문서  │
│  │   → 공내역서와 별개의 독립 문서           │
│  │                                      │
│  ├─ 세금계산서 (수동 입력 또는 연동)         │
│  │   → 매출: 우리가 발행한 것              │
│  │   → 매입: 자재/서비스 구매 시 받은 것     │
│  │                                      │
│  └─ 하자보증보험 (PDF 스캔본 업로드)        │
│      → 공사 완료 후 발행                   │
│      → OCR로 핵심 정보 자동 추출           │
└─────────────────────────────────────────┘
```

### 2.2 문서별 상세

#### 공내역서
- 발주처에서 카톡/이메일로 받는 엑셀 파일
- 발주처가 요구하는 공사 항목, 규격, 수량 등이 적혀 있음
- 시스템에서의 역할: 원본 파일 보관 + 내용 열람
- 우리가 수정하는 문서가 아님 (발주처 원본 그대로 보관)

#### 견적서
- 우리가 직접 작성하는 문서 (엑셀 파일)
- 품명, 규격, 수량, 단가, 금액 등을 우리가 직접 산정
- 공내역서를 참고하되, 단가는 우리가 별도로 정함
- 한 현장에 견적서가 여러 개일 수 있음 (본공사 + 추가공사)
- 시스템에서의 역할: 파일 업로드 + 금액 데이터 파싱 저장 → 매출 계산 기준

#### 세금계산서
- 매출 세금계산서: 우리가 발주처에 발행
- 매입 세금계산서: 자재/서비스 구매 시 받음
- 시스템에서의 역할: 수동 입력 (공급가액, 세액, 거래처, 날짜)
- 미수금 추적: 매출 세금계산서 발행했는데 입금 안 된 건 자동 표시

#### 하자보증보험
- 공사 완료 후 발행하는 보험 문서
- PDF 스캔본(이미지 형태)으로 존재
- 시스템에서의 역할: PDF 업로드 + OCR로 핵심 정보 추출 (보험기간, 보증금액, 현장명)
- 만료일 접근 시 알림 (D-30, D-7)

## 3. 기능 목록

### 3.1 현장 관리
- 현장 생성/수정/삭제
- 현장 상태 관리: 진행중 / 정산중 / 완료 / 하자보증기간
- 현장 상세: 해당 현장의 모든 문서 + 손익을 한 화면에서 확인
- 거래처(발주처) 관리: 어떤 발주처와 몇 건, 미수금 얼마

### 3.2 문서 업로드/관리
- 공내역서: 엑셀 파일 업로드 + 원본 보관 + 내용 뷰어
- 견적서: 엑셀 파일 업로드 + 금액 데이터 파싱 저장 + 내용 뷰어
- 세금계산서: 수동 입력 폼 (매출/매입 구분)
- 하자보증보험: PDF 업로드 + OCR 자동 추출 + 만료 알림

### 3.3 손익 관리
- 현장별 손익: 매출(견적서 합계) - 매입(매입 세금계산서 합계) = 마진
- 마진율: 마진 / 매출 × 100
- 미수금: 매출 세금계산서 합계 - 입금 확인 금액
- 전체 현장 종합: 진행중 현장 총 마진, 총 미수금

### 3.4 AI 챗봇 (RAG)
- 웹 화면 내 플로팅 채팅창
- 현장 데이터에 대해 자연어로 질문
- 예시 질문:
  - "강남 현장 마진 얼마야?"
  - "미수금 가장 많은 현장은?"
  - "하자보증보험 곧 만료되는 거 있어?"
  - "이번 달 매출 합계 얼마야?"
  - "○○건설한테 미수금 얼마 남았어?"
- 동작 방식:
  1. 사용자 질문 → 챗봇 API
  2. 의도 파악 (LLM function calling)
  3. 필요한 데이터 DB 조회 + 타 서비스 OpenFeign 호출
  4. 조회 결과 + 질문 → LLM 컨텍스트 주입 → 답변 생성
  5. SSE 스트리밍으로 프론트에 전달
- 정형 데이터(MySQL)는 SQL 조회 → LLM 주입 (벡터DB 불필요)

### 3.5 AI 요약 대시보드
- 현장 선택 시 LLM이 자연어 요약 생성
- "이 현장은 매출 5,200만원, 매입 3,800만원, 마진율 26.9%, 미수금 800만원이 45일째 미회수입니다"
- 전체 현장 종합 요약도 가능

### 3.6 알림
- 하자보증보험 만료 임박 (D-30, D-7)
- 미수금 연체 알림 (30일/60일/90일 초과)
- 인앱 알림 (웹 화면 내 알림 벨)

### 3.7 인증/권한
- 혜민: ADMIN — 모든 기능 접근
- 아버지: VIEWER — 대시보드/현장 정보 열람만 가능, 수정 불가

## 4. 현장 문서 라이프사이클

```
1. 수주
   발주처에서 공내역서 수신 (카톡/이메일)
   → 공내역서 엑셀 파일 업로드
   → 우리가 별도로 견적서 작성 후 엑셀 파일 업로드
   → 계약 확정 → 현장 생성

2. 시공
   → 자재/서비스 매입 시 세금계산서(매입) 등록
   → 발주처에 세금계산서(매출) 발행 등록
   → 추가공사 발생 시 견적서 추가 업로드

3. 정산
   → 미수금 확인 (매출 세금계산서 vs 입금 내역)
   → 입금 확인 처리
   → 현장 손익 확정

4. 완료
   → 하자보증보험 PDF 업로드 + OCR
   → 현장 상태 → 하자보증기간
   → 보험 만료 후 → 현장 마감(완료)
```

## 5. 화면 구성 (초안)

### 5.1 주요 화면
- 로그인
- 대시보드 (전체 현장 종합 — 총 매출, 총 마진, 총 미수금, 진행중 현장 수)
- 현장 목록 (상태별 필터, 검색)
- 현장 상세 (문서 4종 탭 + 손익 요약 + AI 요약)
- 거래처 목록/상세
- 알림 목록
- 플로팅 AI 챗봇 (모든 화면에서 접근 가능)

### 5.2 현장 상세 화면 구조
```
[현장명: 강남 리모델링]  [상태: 시공중]  [발주처: ○○건설]

[AI 요약]
"매출 5,200만원, 매입 3,800만원, 마진 1,400만원(26.9%)
 미수금 800만원 (45일 경과)"

[탭: 공내역서 | 견적서 | 세금계산서 | 하자보증보험 | 손익]

── 공내역서 탭 ──
  파일 업로드 영역 + 업로드된 파일 목록 + 내용 뷰어

── 견적서 탭 ──
  파일 업로드 영역 + 업로드된 파일 목록 + 금액 요약

── 세금계산서 탭 ──
  매출/매입 구분 + 입력 폼 + 목록 + 미수금 강조 표시

── 하자보증보험 탭 ──
  PDF 업로드 + OCR 결과 표시 + 만료일 카운트다운

── 손익 탭 ──
  매출 합계 / 매입 합계 / 마진 / 마진율 / 미수금
```

## 6. 손익 계산 공식

```
현장 매출 = SUM(해당 현장의 모든 견적서 금액)
현장 매입 = SUM(해당 현장의 모든 매입 세금계산서 공급가액)
현장 마진 = 매출 - 매입
마진율(%) = 마진 / 매출 × 100
미수금 = SUM(매출 세금계산서 공급가액) - SUM(입금 확인 금액)
```

## 7. 비기능 요구사항

- 로컬 환경에서 Docker Compose로 실행 가능
- 1~2명 동시 사용 (혜민 + 아버지)
- 데이터 백업: MySQL dump 주기적 실행 (로컬 저장)
- 파일 저장: 로컬 파일시스템 (추후 S3 전환 가능한 구조)
- 보안: JWT 인증, 환경변수로 민감 정보 분리

## 9. MVP 범위

### MVP에 포함
- 현장 CRUD + 상태 관리
- 공내역서/견적서 파일 업로드 + 보관 + 뷰어
- 세금계산서 수동 입력 + 미수금 추적
- 현장별 손익 계산 + 대시보드
- 전체 현장 종합 대시보드
- 인증 (ADMIN/VIEWER)
- AI 챗봇 (RAG)

### MVP 이후
- 하자보증보험 PDF + OCR
- AI 요약 리포트
- 만료/연체 알림
- 거래처 관리
- 엑셀 내용 파싱 뷰어 (Apache POI로 셀 데이터 표시)
- 홈택스 세금계산서 스크래핑 연동
