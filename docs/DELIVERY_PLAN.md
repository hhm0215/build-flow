# BuildFlow V1 완료·진행률 기준선

> 이 문서는 **첫 실데이터 현장 1건을 안전하게 운영하는 V1**의 범위·완료 조건·진행률 기준이다. 작업 우선순위와 세부 상태는 `.claude/BACKLOG.md`, 실제 검증 근거는 `.claude/PROGRESS.md`·`docs/PILOT_QA.md`·`docs/SECURITY_OPERATIONS.md`를 따른다. 장기 범용 정보관리 플랫폼(`docs/PRODUCT_VISION.md`) 전체의 완성률이 아니다.

## 완료선과 즉시 실행 순서

사용자가 정한 출시일은 없다. 이전에 적은 날짜는 사용자와 합의하지 않은 추정이므로 폐기한다. 선행 조건을 통과하는 즉시 다음 단계로 진행하며, 질문 답변을 기다리는 동안 독립적인 개발·검증을 계속한다. 필요한 업무 판단은 `docs/PILOT_QA.md`에 모은다.

| 순서 | 체크포인트 | 통과 증거 |
|---:|---|---|
| 1 | 데이터 복구 | 7개 DB와 업로드 파일의 일관된 외부 백업, 체크섬, 빈 환경 격리 복원, 관리자 로그인·파일 참조 검증 |
| 2 | 스키마 안전성 | 서비스별 버전 마이그레이션과 런타임 DB 최소 권한, 기존 데이터 보존·롤백 검증 |
| 3 | 핵심 업무 동선 | 합성 데이터로 거래처→현장→견적→매입→세금계산서→보증의 생성/수정/조회와 금액·참조 무결성 검증. 미지원 동작은 화면에서 명확히 차단 |
| 4 | 운영 반영·복귀 | 고정 SHA·필수 CI·순차 배포, health·401, 실패 중단/롤백, 운영 알림 수신 실측 |
| 5 | 첫 현장 인수 | 사용자와 현장 1건의 금액·버전·관계 확인, 복구/접속 재점검, Critical/High 미해결 0건, 운영 개시 판단 |

백업/마이그레이션과 CRUD 결함 수리는 병렬로 진행한다. **실데이터 입력은 복구·마이그레이션·보안 게이트 후**로 제한하며, 공개 HTTPS는 그 전까지 테스트 데이터 전용이다. USB 제한 가져오기·AI 자동화는 수동 입력의 안전한 첫 현장 운영과 분리해 후속으로 진행할 수 있지만, 필요한 업무 기능의 제외는 사용자에게 범위를 명확히 알린다. USB 원본은 변경하지 않는다.

## 2026-10-12 기준선: 40/100점 (추정, ±10점)

점수는 기능 개수나 커밋 수가 아닌 **V1 완료 기준의 가중 진척도**다. 부분 점수는 지금까지 확인한 구현·합성 QA에 대한 추정이며, 해당 영역의 운영 게이트를 통과했다는 뜻이 아니다. 증거가 없으면 `PENDING/UNVERIFIED`를 `PASS`로 올리지 않는다.

| 영역 | 배점 | 현재 인정 | 남은 완료 조건 |
|---|---:|---:|---|
| 첫 현장 핵심 업무 동선 | 35 | 20 | 거래처·현장·견적·매입·세금계산서·보증의 생성/수정/조회·금액/참조 정합성·필요한 PDF 확인. 미지원 삭제/AI는 명시적으로 차단하고 후속 범위를 안내 |
| DB·원본 데이터 안전성 | 35 | 8 | 업로드 포함 외부 백업·격리 복원, 7개 스키마 마이그레이션, 최소 권한 |
| 보안·CI/CD·운영 복귀 | 25 | 12 | 필수 CI 강제, 실제 이미지 digest·배포/롤백, 알림 실수신, 미해결 공개 게이트 |
| 첫 실데이터 현장 인수 | 5 | 0 | 사용자 금액 검토와 운영 수락 |
| **합계** | **100** | **40** | **실측 게이트 통과 시 첫 현장 운영** |

현재 공개 사이트 접속·로그인과 일부 생성/수정/집계는 가능하지만 이를 **운영 V1 완료**로 부르지 않는다. `main` CI의 릴리스 후보 artifact는 배포가 아니며, VPS 자동 CD·실데이터 입력은 미승인/미완료다.

2026-10-14 PR #97의 OCR·만료 알림 안전장치가 `main`에 병합되고 CI가 통과했지만, 실제 MySQL 마이그레이션·구 outbox 감사·VPS 검증이 남아 있어 공개 테스트 서버에는 반영하지 않았다. 이 단계로 V1 점수는 올리지 않는다.

2026-10-15 혼합 PDF의 부분 추출 병합·상충 시 수동 확인 처리를 로컬에서 보강했다. 전체 Gradle·프론트 lint/테스트/빌드는 통과했으나, 실제 혼합 PDF·PR/CI·VPS 실측 전에는 업무 동선 완료로 계산하지 않으며 V1은 40/100이다.

2026-10-15 발행 전 구 outbox 억제 코드를 로컬 H2/JPA와 전체 백엔드 테스트로 검증했으나 운영 MySQL DDL·큐/롤백 실측이 남았다. 코드 통합 또는 CI 통과만으로 스키마 안전성·VPS 배포 점수를 올리지 않으므로 **40/100 유지**한다.

2026-10-16 업로드 PDF 사본의 관리자 전용 다운로드를 작업 분기에서 구현 중이다. 이는 원본 대조 접근의 일부일 뿐, 확인자 감사·보존 정책·DB와 파일의 격리 복원·VPS 실측을 대신하지 않는다. **40/100**은 유지하며, 필수 게이트를 통과하는 즉시 운영으로 진행한다.

2026-10-16 원본 접근은 PR #101로 `develop` 통합·CI 통과했고 `main`/VPS는 미반영이다. 같은 날 DB 행·보증 파일 manifest 참조의 오프라인 합성 대조를 추가했다. 실제 백업 생성·격리 복원·행 추출 출처와 관리자 로그인은 아직 통과하지 않아 복구 체크포인트 점수와 **40/100**은 그대로다.

## 회사 PC에서 작업 현황 확인

- **진행·대기 요청**: Codex/ChatGPT 앱의 이 BuildFlow 채팅과 `Scheduled`에서 자동 실행의 최근 결과·사용자 조치 요청을 확인한다. 현재 연결된 로컬 채팅의 파일 작업은 집 PC와 앱이 켜져 있어야 진행된다. 회사 PC에서 같은 채팅을 제어하려면 앱의 원격 연결이 필요하다.
- **할 일·완료 근거**: [BACKLOG](../.claude/BACKLOG.md)가 우선순위의 단일 진실원이고, [PROGRESS](../.claude/PROGRESS.md)가 완료 이력이다. 이 문서는 V1 점수·체크포인트를 관리한다. 질문은 QA 문서에 모으되 답이 없다는 이유로 무관한 작업을 멈추지 않는다.
- **코드 통합 상태**: [Pull requests](https://github.com/hhm0215/build-flow/pulls)에서 리뷰·병합, [Actions](https://github.com/hhm0215/build-flow/actions)에서 CI를 확인한다. 로컬 미커밋 변경·예약 실행 중인 작업은 GitHub에 바로 표시되지 않는다.
- **운영 반영 상태**: `PROGRESS`의 VPS SHA·검증 기록과 [보안 게이트](SECURITY_OPERATIONS.md)를 확인한다. PR 병합·CI 성공을 VPS 배포 또는 실데이터 운영 승인으로 계산하지 않는다.

`Scheduled`와 GitHub는 서로 다른 상태를 보여준다. 전자는 에이전트 실행 결과, 후자는 공유된 코드·CI 이력이다. 회사 PC에서 집 PC 전원과 무관하게 코드를 개발하려면 별도의 Codex Cloud 환경이 필요하며, USB 원본·로컬 브라우저 세션은 그 환경으로 자동 이전되지 않는다.

## 범위 고정과 진행률 갱신 규칙

- V1 100%는 **첫 실데이터 현장 1건을 안전하게 입력·조회·수정·복구·운영하는 것**이다. USB `견적서/2026` `.xlsx` 제한 가져오기와 원본·출처·버전 검토는 중요한 후속 작업이지만 수동 입력 첫 현장의 운영 개시를 막는 선행 조건으로 계산하지 않는다. 전체 USB 일괄 적재, 모든 파일 형식, 멀티테넌시, 범용 플랫폼, 고급 AI 자동 확정도 V1 밖이다. AI는 금액·관계·삭제를 사용자 확인 없이 확정하지 않는다.
- 각 변경 후 해당 체크포인트의 **검증 근거가 새로 통과할 때만** 현재 인정 점수를 조정한다. 코드만 작성, CI만 통과, 릴리스 후보 생성, 화면만 열림으로 운영/복구 항목을 100% 처리하지 않는다.
- 매 작업 종료 보고에 `현재 N/100`, 완료된 체크포인트, 바로 다음 게이트, 위험/사용자 판단을 짧게 적는다. 점수가 그대로여도 막힌 원인과 다음 행동을 밝힌다.
- 막힘이 생기면 즉시 원인·회복 행동을 백로그에 반영한다. 사용자가 요청하지 않은 목표일을 새로 만들지 않으며 필수 보안·데이터 보존 범위는 속도를 위해 축소하지 않는다.
