# BuildFlow V1 납기·진행률 기준선

> 기준일: 2026-10-12 (Asia/Seoul). 이 문서는 **첫 실데이터 현장 1건을 안전하게 운영하는 V1**의 범위·목표일·진행률 기준이다. 작업 우선순위와 세부 상태는 `.claude/BACKLOG.md`, 실제 검증 근거는 `.claude/PROGRESS.md`·`docs/PILOT_QA.md`·`docs/SECURITY_OPERATIONS.md`를 따른다. 장기 범용 정보관리 플랫폼(`docs/PRODUCT_VISION.md`) 전체의 완성률이 아니다.

## 완료선과 일정

**V1 100% 목표일: 2026-12-11.** 이는 1인 개발을 지속할 수 있고 필요한 사용자 판단·접근 수단이 영업일 1일 이내 제공된다는 가정의 **목표일**이지 안전 게이트를 생략하는 무조건적인 출시 약속이 아니다. 일정이 밀리면 완료율을 올려 보이거나 실데이터 게이트를 우회하지 않고, 원인·새 예상일·줄일 수 있는 비필수 범위를 같은 보고에 적는다.

목표일은 **작업 대기일이나 에이전트 정지 조건이 아니다**. 선행 작업과 안전 게이트가 준비되면 날짜와 관계없이 바로 진행한다. 사용자의 UX·업무 규칙 답변이 아직 없어도 독립적인 테스트·결함 수리·복구 준비는 계속하고, 필요한 질문만 `docs/PILOT_QA.md`의 업무 흐름 표에 모아 전달한다.

|---|---|---|
| QA 범위 고정 | 2026-10-23 | `docs/PILOT_QA.md`의 실패 재현·보관 정책·AI 제공 방식과 미지원 업무 규칙을 확정/보류로 분류 |

백업/마이그레이션과 CRUD 결함 수리는 병렬로 진행하되 **실데이터 입력은 복구·마이그레이션·보안 게이트 후**로 제한한다. 공개 HTTPS는 그 전까지 테스트 데이터 전용이다. AI 모델 비용·성능·개인정보 전송 방식의 선택이 늦거나 복구 실측이 실패하면 목표일을 즉시 재산정한다.

## 회사 PC에서 작업 현황 확인

- **진행·대기 요청**: Codex/ChatGPT 앱의 이 BuildFlow 채팅과 `Scheduled`에서 자동 실행의 최근 결과·사용자 조치 요청을 확인한다. 현재 연결된 로컬 채팅의 파일 작업은 집 PC와 앱이 켜져 있어야 진행된다. 회사 PC에서 같은 채팅을 제어하려면 앱의 원격 연결이 필요하다.
- **할 일·완료 근거**: [BACKLOG](../.claude/BACKLOG.md)가 우선순위의 단일 진실원이고, [PROGRESS](../.claude/PROGRESS.md)가 완료 이력이다. 이 문서는 V1 점수·체크포인트를 관리한다. 질문은 QA 문서에 모으되 답이 없다는 이유로 무관한 작업을 멈추지 않는다.
- **코드 통합 상태**: [Pull requests](https://github.com/hhm0215/build-flow/pulls)에서 리뷰·병합, [Actions](https://github.com/hhm0215/build-flow/actions)에서 CI를 확인한다. 로컬 미커밋 변경·예약 실행 중인 작업은 GitHub에 바로 표시되지 않는다.
- **운영 반영 상태**: `PROGRESS`의 VPS SHA·검증 기록과 [보안 게이트](SECURITY_OPERATIONS.md)를 확인한다. PR 병합·CI 성공을 VPS 배포 또는 실데이터 운영 승인으로 계산하지 않는다.

`Scheduled`와 GitHub는 서로 다른 상태를 보여준다. 전자는 에이전트 실행 결과, 후자는 공유된 코드·CI 이력이다. 회사 PC에서 집 PC 전원과 무관하게 코드를 개발하려면 별도의 Codex Cloud 환경이 필요하며, USB 원본·로컬 브라우저 세션은 그 환경으로 자동 이전되지 않는다.

## 범위 고정과 진행률 갱신 규칙

- V1에는 **첫 현장 1건**과 `견적서/2026` `.xlsx` 제한 가져오기만 포함한다. USB 전체 일괄 적재, 모든 파일 형식, 멀티테넌시, 범용 플랫폼, 고급 AI 자동 확정은 V1 밖으로 둔다. AI는 금액·관계·삭제를 사용자 확인 없이 확정하지 않는다.
- 각 변경 후 해당 체크포인트의 **검증 근거가 새로 통과할 때만** 현재 인정 점수를 조정한다. 코드만 작성, CI만 통과, 릴리스 후보 생성, 화면만 열림으로 운영/복구 항목을 100% 처리하지 않는다.
- 매 작업 종료 보고에 `현재 N/100`, 완료된 체크포인트, 다음 목표일·게이트, 일정 위험/사용자 판단을 한두 줄로 적는다. 점수가 그대로여도 막힌 원인과 다음 행동을 밝힌다.
- 목표일을 넘기거나 막힘이 영업일 2일 이상 지속되면 원인·회복 계획·수정 목표일을 이 문서와 백로그에 반영한다. 필수 보안·데이터 보존 범위는 일정 때문에 축소하지 않는다.
