# 로컬 업무 엑셀 가져오기

가족이 보관해 온 업무 엑셀을 **로컬 개발 환경 DB에만** 현장 단위로 적재하는 절차다. 운영 VPS는 대상이 아니다. 도구는 `scripts/import/`(Python 표준 라이브러리 + openpyxl·xlrd)이며, 1차 범위는 견적서 엑셀(.xlsx, .xls)이다.

## 원칙

1. **원본은 읽기 전용** — 파일을 바이트로 한 번 읽어 SHA-256과 파싱에 함께 쓴다. 원본 쓰기·이동·이름 변경은 하지 않는다. 오류를 고쳐야 하면 원본이 아니라 별도 사본을 고쳐 그 사본을 넣는다.
2. **DB 직접 쓰기 금지** — Gateway API(기본 `http://localhost:3000`, 프론트 Nginx 경유)로만 거래처·현장·견적을 만든다. 서버 검증·현장 참조 검증·Kafka 손익 재계산이 화면 입력과 똑같이 돈다.
3. **기본은 미리보기** — `--apply`가 없으면 API를 한 번도 호출하지 않는다. 미리보기에 ERROR가 하나라도 있으면 `--apply`·`--emit-plan`을 거부한다(강제 옵션 없음). ERROR는 아니지만 사용자 판단이 필요한 항목은 **확인 필요**로 표시하고, 안내된 옵션으로 확정하기 전에는 역시 적용을 거부한다.
4. **적재 기록(ledger)으로 멱등** — 저장소 밖 JSONL(기본 `%USERPROFILE%\Documents\Dev\build-flow-backups\import-ledger.jsonl`)에 대상 주소·파일 SHA-256·시트·품목 행 범위 → 생성된 견적·현장·거래처 id, 견적일과 그 출처를 남긴다. 같은 대상·파일·시트는 다시 넣지 않는다. 기록이 사라져도 견적 메모의 `로컬 가져오기 sha256:<앞 16자리>` 표식으로 기존 견적을 찾아 중복 생성을 막는다. 같은 바이트의 사본 파일은 처음 것만 넣는다.
5. **토큰은 환경변수로만** — `BUILDFLOW_ACCESS_TOKEN`(+ 선택 `BUILDFLOW_REFRESH_TOKEN`)만 읽고 출력·저장하지 않는다. 비밀번호 입력 기능은 없다. 환경 프록시를 쓰지 않고 리다이렉트도 따르지 않는다.
6. **출력 최소화** — 콘솔에는 파일명·거래처/현장명·품목 수·합계·검증 결과만 나온다. 로그 파일은 만들지 않는다. 대상 주소는 localhost/127.0.0.1/::1만 허용한다.

실데이터를 넣기 전에는 `docs/SECURITY_OPERATIONS.md`의 실데이터 게이트(백업·복원 확인)를 먼저 따른다.

## 견적서 양식과 변환 규칙

| 위치(0-based 행, 열) | 의미 |
|---|---|
| 3행 C열 근처 | `YYYY년` 표기 — 날짜로 쓰지 않고 연도만 추출 |
| 4행 C열 | 수신처(거래처명). 끝의 `귀하`·`귀중` 등은 뗀다 |
| 5행 F열 | 현장명 |
| 10행 G열 | 합계금액(숫자 또는 `₩1,234,000` 같은 글자) |
| 11행 | 머리글 `NO.` `품명` `사이즈` `규격` `수량` `총수량` `단가` `금액` `비고` |
| 12행~ | 품목 |

- 열 위치는 머리글 텍스트로 찾는다. 머리글을 못 찾은 열만 고정 위치(B·C·F·H·I·J·K·M·P)로 폴백하고 경고를 낸다.
- 수량·단가가 있으면 그대로 쓴다. 수량×단가와 금액 셀이 다르면 경고(총수량×단가가 맞으면 총수량 사용).
- 금액만 있으면 수량 1·단가=금액·단위 `식`으로 바꾸고, 원래 규격은 품명 괄호에 남긴다.
- 규격(H열)은 단위로 쓴다. 비었으면 `식`, 20자를 넘으면 `식`으로 두고 품명에 덧붙인다.
- 품명이 빈 행(번호·0원만 있는 행)과 `합계`·`소계`·`부가세` 행은 건너뛴다. 품명 없이 금액만 있는 행, 음수(할인) 행, 소수 2자리를 넘는 값은 ERROR다.
- 서버는 항목 금액을 수량×단가로 다시 계산한다. 그래서 **품목 합계(Σ 수량×단가) ≠ 합계금액 셀이면 ERROR**다.
- `--append-size`, `--append-note`로 사이즈·비고를 품명 뒤 괄호에 덧붙일 수 있다(기본 꺼짐).

### 병합 셀

- xlsx는 병합 범위를 읽기 위해 openpyxl 일반 모드(`read_only=False`)로 연다. xls는 xlrd `formatting_info=True`로 병합 범위를 읽고, 서식 정보를 못 읽는 파일만 병합 없이 다시 연다.
- **머리글 위 영역**(수신처·현장명·합계금액): 병합 범위 전체에 왼쪽 위 값을 채운다. 그래서 현장명이 E~H열 병합(값은 E열)이어도 F열 위치에서 읽힌다.
- **품목 영역**: 품명·규격·사이즈·비고 같은 글자 열만 세로 병합 아래 행에 값을 물려준다. 수량·단가·금액은 물려주지 않는다(같은 금액을 두 번 세지 않기 위해).
  - 물려받은 품명 행에 금액이 있으면 **같은 품명의 별도 품목**으로 넣는다(행마다 규격·수량·단가가 다른 세부 행). 미리보기에 `병합된 품명을 아래 행 N개에 물려줌` 경고가 나온다.
  - 물려받은 품명 행에 금액이 없으면(높은 행 하나를 병합으로 만든 양식) 금액 없는 품명 행으로 빠진다.
  - 병합이 아닌데 품명 칸만 빈 행에 금액이 있으면 그대로 ERROR다.

### 합계 셀이 계산값 없는 수식

- openpyxl로 만든 파일처럼 수식만 있고 저장된 계산값이 없으면 ERROR 대신 경고 `합계 셀 계산값 없음(수식) — 품목 합계로 검증 불가`를 내고 **확인 필요**로 둔다.
- 품목 합계만으로 넣어도 되면 `--allow-missing-total`을 준다. 가능하면 엑셀에서 한 번 열어 저장한 사본(계산값 포함)을 넣는 편이 낫다.
- 합계 칸이 그냥 비었거나 숫자가 아니면 기존대로 ERROR다.

### 현장명: 같은 현장 후보·별칭·폴더 이름

- 현장명 정규화 키 = 전각 영숫자·기호를 반각으로 바꾸고 공백·괄호·기호를 모두 없앤 뒤 소문자로(예: `합성 마트`·`합성마트`·`합성마트()`는 같은 키). **글자 오타(받침이 다른 글자 등)는 고치지 않는다.**
- 같은 키인데 표기가 다른 이름들은 미리보기에 `같은 현장 후보(미확정)`으로 묶어 보여 주고, 별칭으로 확정하기 전에는 적용을 거부한다. 글자만 조금 다른 이름 쌍은 `비슷한 현장명(자동으로 묶지 않음)`으로 참고만 보여 준다.
- `--site-alias <파일>`: 원본 현장명 → 적재 현장명. 원본은 정규화 키로 비교하므로 띄어쓰기·기호 차이는 한 줄로 덮인다. 파일은 **저장소 밖**에 두며 형식은 둘 중 하나다.
  - CSV(UTF-8, 첫 줄 머리글 `원본,적재`·`#` 주석 허용): `합성마트,합성마트 본점`
  - JSON 객체(`.json`): `{"합성마트": "합성마트 본점"}`
  - 같은 원본 키에 적재 이름이 둘이면 설정 오류로 멈춘다.
- 적용 시 서버에 이름은 다르지만 정규화 키가 같은 기존 현장이 있으면 새로 만들지 않고 멈춘다. 별칭으로 기존 현장 이름에 맞춘 뒤 다시 실행한다.
- 현장명 셀이 비어 있으면 파일이 든 폴더 이름(연도 폴더 제외)을 후보로 미리보기에 보여 준다. `--site-from-folder`를 줄 때만 그 이름을 쓰고, 미리보기 현장명에 `(출처: 폴더 이름)`을 붙인다. 폴더 이름에도 별칭이 적용된다.

### 품목 없는 견적

- 품목이 0개면 기본은 ERROR다. `--lump-when-empty`를 주면 합계금액 셀 값으로 `<파일명> (합계 1식)` 품목 하나(수량 1·단위 `식`)를 만든다. 합계 셀도 비면 ERROR를 유지한다.

### 날짜 원칙

- 견적일: 머리글 위 셀에 날짜(날짜 셀 또는 `2025.03.04`·`2025년 3월 4일` 같은 글자)가 있으면 그 값(`file-cell R?C?`). 없으면 파일 수정 시각의 로컬 날짜(`file-mtime`). 출처는 미리보기와 적재 기록에 남는다.
- 시트의 `YYYY년` 연도 표기는 날짜로 쓰지 않는다. **새로 만드는 현장**에만 메모 `견적서 표기 연도 YYYY`로 남기고, 기존 현장 메모는 덮어쓰지 않는다.
- 현장 시작·종료일은 추정하지 않고 비워 둔다.
- 상위 폴더 이름이 연도(예: `2026`)이고 시트 표기 연도와 다르면 미리보기에 경고한다.

### 거래처·현장·확정

- 거래처·현장은 이름이 정확히 같은 기존 항목을 재사용하고, 없으면 만든다. 같은 이름이 둘 이상이거나 보관된 항목과 이름이 같으면 멈추고 정리를 요청한다.
- 기존 현장의 거래처가 견적 수신처와 다르면 경고만 하고 현장은 바꾸지 않는다.
- 견적은 모두 `ORIGINAL` 초안(DRAFT)으로 넣는다. `--confirm-latest`를 주면 현장별로 가장 최근(견적일 → 수정일 → 파일명 순) 파일만 확정한다. 기본은 꺼짐.
- `--complete-sites`를 주면 이번 실행의 현장 상태를 `PATCH /api/v1/sites/{id}/status`로 `COMPLETED`로 바꾼다. 이미 완료·보관된 현장, 수주 전(`BIDDING`, 서버가 완료로 바로 바꾸지 않음) 현장은 건너뛴다. 변경은 적재 기록에 `kind=site-status`로 남는다.

### 옵션 요약

| 옵션 | 효과 |
|---|---|
| `--apply` | Gateway API로 실제 생성(토큰 환경변수 필요) |
| `--emit-plan <JSON>` | API 호출 없이 브라우저 적용용 계획 JSON을 저장소 밖에 저장 |
| `--record-result <JSON>` | 브라우저 적용 결과를 적재 기록에 남김(경로 인자 없이 단독) |
| `--confirm-latest` | 현장별 가장 최근 파일만 확정 |
| `--complete-sites` | 현장 상태를 완료로 변경 |
| `--site-alias <CSV/JSON>` | 원본 현장명 → 적재 현장명 확정 |
| `--site-from-folder` | 현장명 셀이 비면 폴더 이름 사용 |
| `--lump-when-empty` | 품목 0개면 합계 1식 품목 생성 |
| `--allow-missing-total` | 계산값 없는 수식 합계를 품목 합계로 진행 |
| `--append-size` / `--append-note` | 사이즈·비고를 품명 괄호에 덧붙임 |
| `--recursive` | 하위 폴더까지 찾기 |

## 절차

1. **백업**: 로컬 스택 DB를 먼저 백업한다(`docs/DATABASE_OPERATIONS.md`). USB 원본은 가능하면 쓰기 방지 상태로 연결하고, 작업용 사본 폴더를 따로 둔다.
2. **미리보기**:
   ```bash
   python -I -X utf8 scripts/import/estimates.py "<연도>\<현장 폴더>"
   ```
   여러 경로를 한 번에 줄 수 있고, `--recursive`로 하위 폴더까지 찾는다. 숨김·`~$` 임시 파일은 건너뛴다.
3. **ERROR 정리**: ERROR 파일은 사본을 고치거나, 해당 파일을 빼고 나머지 파일 경로만 지정한다.
4. **토큰 준비**: 로컬 화면에서 로그인한 뒤 액세스 토큰을 현재 셸의 환경변수에만 넣는다. 셸 기록·파일에 남기지 않는다.
5. **적용**:
   ```bash
   python -I -X utf8 scripts/import/estimates.py "<현장 폴더>" --apply [--confirm-latest] [--base-url http://localhost:3000] [--ledger <저장소 밖 경로>]
   ```
   중간에 실패해도 앞서 생성된 항목은 적재 기록에 남아, 다시 실행하면 이어서 진행한다.
   토큰을 환경변수로 옮기지 않고 로그인된 브라우저 세션으로 넣으려면 아래 "브라우저 세션 적재"를 따른다.
6. **확인**: 화면에서 현장·견적·손익을 확인한다. 리프레시 토큰으로 회전했다면 환경변수의 리프레시 토큰은 더 이상 쓰지 않는다.

## 브라우저 세션 적재

토큰을 셸 환경변수로 꺼내지 않고, 사용자가 로그인한 로컬 BuildFlow 페이지에서 같은 규칙으로 적용하는 경로다. 에이전트는 브라우저 토큰을 다루지 않는다.

1. **계획 내보내기**(API 호출 없음, ERROR·확인 필요가 없어야 함):
   ```bash
   python -I -X utf8 scripts/import/estimates.py "<현장 폴더>" --emit-plan "<저장소 밖>\plan.json" [--base-url http://localhost:3000] [--confirm-latest] [--complete-sites] [--site-alias ...]
   ```
   계획에는 `format=buildflow-import-plan`, `version=1`, 대상 `baseUrl`, 옵션, `entries`(파일 SHA-256·시트·행 범위·견적일과 출처, 거래처명·현장명·현장명 출처, 새 현장 메모, sha 표식, 견적 본문, 확정 여부), `known`(이미 적재 기록에 있어 확정·완료 처리만 필요한 견적·현장 id)이 들어간다. 토큰과 원본 경로는 넣지 않는다. 이미 적재 기록에 있는 파일·같은 내용 사본은 빠진다.
2. **페이지 콘솔에서 적용**: `--base-url`과 같은 주소의 로그인된 BuildFlow 탭에서 개발자 도구 콘솔을 열고 `scripts/import/browser_apply.js` 내용을 붙여 넣은 뒤:
   ```js
   const result = await buildflowApplyPlan(/* plan.json 내용 붙여 넣기 */)
   copy(JSON.stringify(result, null, 2))   // 저장소 밖 result.json으로 저장
   ```
   - 로컬 호스트(localhost/127.0.0.1/::1) 페이지에서만, 계획의 `baseUrl`과 페이지 주소가 같을 때만 실행한다.
   - 토큰은 페이지 `localStorage`(`buildflow-auth`)에서 요청마다 읽어 Authorization 헤더에만 쓰며 결과·오류 메시지에 넣지 않는다. 리다이렉트를 따르지 않는다.
   - 규칙은 `--apply`와 같다: 거래처·현장 목록 GET → 이름이 정확히 같은 항목 재사용(둘 이상·보관 항목·정규화 키만 같은 기존 현장이면 멈춤) → 현장별 견적 GET으로 sha 표식 확인 → 없을 때만 POST → 확정 대상만 DRAFT일 때 확정 → 선택 시 현장 상태 COMPLETED.
   - 결과(`format=buildflow-import-result`)는 `ok`, `error`, 파일별 `estimateId`·`siteId`·`clientId`·`created*`·`status`·`action(created|linked)`, `siteStatus`, `skipped`를 담는다. 401이면 멈추고 다시 로그인 후 같은 계획으로 재실행하라고 안내한다(이미 넣은 견적은 표식으로 연결만 한다).
3. **결과 기록**:
   ```bash
   python -I -X utf8 scripts/import/estimates.py --record-result "<저장소 밖>\result.json" [--ledger ...]
   ```
   결과의 `baseUrl`이 로컬 호스트인지, 항목에 sha256·시트·견적·현장 id가 있는지 검사한 뒤 적재 기록에 `appliedVia=browser`로 남긴다. 같은 결과를 다시 기록해도 줄이 늘지 않고, 확정 상태가 바뀐 결과만 한 줄 추가된다. 결과가 `ok=false`(중간 멈춤)이면 넣은 항목까지 기록하고 종료 코드 1을 돌려준다.

계획·결과·별칭 파일에는 실제 현장명·거래처명이 들어가므로 저장소 밖에만 두고(도구가 저장소 안 경로를 거부), 다 쓰면 지운다.

## 되돌리기

- 적재 기록의 `estimateId`·`siteId`·`clientId`, `createdSite`·`createdClient`로 이번에 만든 항목을 확인해 화면 또는 API로 지운다(견적 삭제 → 새로 만든 현장 삭제 또는 보관). 기존 항목을 재사용한 경우(`created*=false`)는 지우지 않는다.
- 크게 잘못 넣었으면 1단계 백업으로 로컬 DB를 복원한다.
- 되돌린 뒤 다시 넣으려면 적재 기록에서 해당 줄을 지운다. 기록을 지워도 견적 메모의 표식이 남아 있으면 기존 견적에 다시 연결되므로, 견적까지 지운 뒤 실행한다.
