# USB 견적서 읽기 전용 목록화 파일럿

이 단계는 파일 바이트의 SHA-256, 상대 경로, 크기, 수정 시각, 숨김 속성을 로컬 비공개 manifest에 기록한다. 문서를 열거나 파싱하지 않고, 파일 복사·VPS 전송·DB 입력·견적 관계/금액 확정도 하지 않는다. USB 원본에는 쓰기·이름 변경·삭제를 수행하지 않는다. OS와 다른 프로그램까지 포함한 물리 매체 무변경 보장은 별도 쓰기 방지 장치가 필요하다.

## 범위와 실행

- 사용자가 명시적으로 지정한 `견적서/2026` 폴더의 `.xlsx`만 읽는다. 실제 절대경로·업체명·파일명·해시를 Git, 채팅, CI 로그에 기록하지 않는다.
- `scripts/usb/inventory-estimates.ps1`에 `-SourceDirectory`와 `-OutputRoot`를 명시한다. 출력은 USB와 다른 **로컬 고정 드라이브**의 클라우드 동기화 대상이 아닌 보호 디렉터리여야 한다. 권장 출력은 Git 제외 `backups/usb-inventory/`다. 네트워크·UNC 경로와 reparse point는 거부한다.
- 스크립트는 매번 새 배치 폴더를 만들고 ACL 상속을 끊어 현재 사용자·SYSTEM·Administrators만 접근 가능하게 한 뒤 `manifest.json`을 쓴다. 기존 manifest는 덮어쓰지 않는다. Git·Docker build context에서 출력 폴더를 제외한다.
- 콘솔에는 배치 ID·건수·바이트·오류 수만 출력한다. 파일별 오류는 manifest의 상대 경로·상태로 확인하고, `completedWithoutErrors=false`인 배치는 승인된 목록으로 사용하지 않는다.

## 검증과 해석 경계

- 파일별 `HASHED`는 읽은 바이트의 SHA-256과 관찰 당시의 크기·수정 시각을 기록했다는 뜻일 뿐, 정상적인 Excel 문서·최신본·수정본·추가공사·손익 반영 대상이라는 뜻이 아니다. 같은 해시라도 출처별 관찰 행을 보존한다.
- 숨김 파일은 목록에 포함하되 `isHidden=true`로 구분하고 자동 가져오기 대상에서 보류한다. 임시 잠금 파일 등일 가능성은 이름만으로 단정하지 않는다.
- 파일 수·누적 바이트 상한, 열기 실패, 읽는 중 변경, reparse point는 성공으로 처리하지 않는다. 경로 재검사는 적대적인 동시 경로 교체를 완전히 막는 기술이 아니므로, 이 파일럿을 임의의 비신뢰 파일시스템으로 확대하지 않는다.
- 본격 원본 사본 가져오기와 업무 데이터 반영은 `docs/SECURITY_OPERATIONS.md`의 실데이터 게이트(DB+파일 외부 백업·격리 복원, 마이그레이션, 최소 권한)가 통과한 뒤 별도 단계로 진행한다. 관계 후보는 사용자의 확정·정정 이력으로 개선하고, AI 판단만으로 금액을 확정하지 않는다.

## 2026-10-04 읽기 전용 점검

- 지정된 연도 폴더의 `.xlsx`는 일반 목록 108개, 숨김 포함 목록 169개(숨김 61개)였다. 두 차례 독립 배치의 상대 경로·크기·수정 시각·SHA-256 관찰값이 모두 일치했고 오류는 0건이었다. 로컬 출력 배치의 ACL 상속 제거와 Git 제외를 확인했다.
- 실제 USB 파일을 수정하거나 VPS로 전송하지 않았다. 목록화는 보관·복원 및 관계 검토 기능 완료를 대신하지 않는다.
