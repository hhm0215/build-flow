# BuildFlow 자동화 워크플로우 가이드

> 사용자가 Claude Code와 BuildFlow 작업을 **얼마나, 어디까지 자동으로 맡길지** 한눈에 보고 운영하기 위한 문서.
>
> 관련 ADR: ADR-010(워크플로우 시스템) / ADR-011(PR 자동화) / ADR-012(위임 모드)
> 마지막 갱신: 2026-06-21

---

## 1. 자동화 3단계 모드

| 모드 | 사이클 안 트리거 | 사이클 간 트리거 | 사용 시점 |
|------|-----------------|-----------------|----------|
| **기본 모드** | 사용자 단계별 승인 | 사용자 명령 | 새로 시작 / 큰 결정 검토 시 |
| **자율 모드** (ADR-011 v2) | 자동 (deny 룰만 차단) | 사용자 명령 | 익숙한 작업 1건 빠르게 |
| **위임 모드** (ADR-012) | 자동 | 자동 (BACKLOG 따라) | 여러 작업 한 번에 + 자리 비울 때 |

---

## 2. 8단계 사이클 (모든 모드 공통)

```
1. BACKLOG 확인 (.claude/BACKLOG.md 최우선 항목)
   ↓
2. 계획 작성 (.claude/plans/YYYY-MM-DD-{slug}.md)
   ↓
3. 구현 + 커밋
   ↓
4. 결과 반영 (계획 결과 / BACKLOG 제거 / PROGRESS 갱신)
   ↓
5. 회고 (실패 있으면 RETROSPECTIVE + 재발 방지 규칙 박기)
   ↓
6. PR 생성 (gh pr create + push 누락 검증)
   ↓
7. PR 자동 머지 (SHA 검증 안전망 통과 시)
   ↓
8. 후처리 (git fetch + PROGRESS 진입점 main SHA 갱신)
```

---

## 3. 위임 모드 진입 키워드

다음 표현을 사용하면 위임 모드 자동 진입:

| 키워드 | 의미 |
|--------|------|
| "BACKLOG P0 다 자동 진행" | P0 항목 전부 비울 때까지 |
| "BACKLOG P1까지 자동 진행" | P0 + P1 전부 |
| "BACKLOG가 빌 때까지" | 전 우선순위 종료까지 (P0/P1/P2 모두) |
| "다음 N개 사이클 자동" | 명시한 사이클 수만큼 |
| "오늘 알아서 끝까지" | 위임 모드 + 멈춤 조건 도달까지 |

---

## 4. 위임 모드 멈춤 조건 (가드레일)

위임 모드는 다음 조건 중 하나라도 만나면 **자동 정지** 후 사용자에게 보고:

1. **BACKLOG 빔** — 지정 범위 (예: P0)가 비었을 때
2. **큰 결정 필요** — 다음 중 하나가 발견되면 `AskUserQuestion`으로 합의:
   - Phase 분할 결정 (작업이 1 PR에 안 들어가는 규모)
   - 외부 의존성 도입 (새 라이브러리, Docker 변경)
   - 주요 설계 결정 (테이블 구조, API 시그니처 변경 등)
   - 추상화 위험 (5페이지 일괄 리팩터처럼 잘못 가면 회복 비용 큰 작업)
3. **빌드/lint/테스트 실패** — 자동 진행 중단, 사용자에게 에러 보고
4. **자율 범위 밖 액션** — `.claude/settings.local.json` `deny` 룰 또는 main 보호 룰에 차단됨

---

## 5. 영구 차단 액션 (어느 모드에서도 막힘)

| 차단 위치 | 대상 |
|-----------|------|
| `settings.local.json` `deny` | `gh pr close`, `gh pr edit --state`, `gh repo delete`, `gh api -X DELETE`, `git push --force`, `--no-verify` |
| main 브랜치 보호 룰 | force-push, delete, 직접 push |
| Claude 자동 분류기 | 위 deny 룰 자동 강제 |

**이 차단을 풀려면 사용자가 명시적으로 settings.local.json을 편집해야 함** — 자동 우회 불가.

---

## 6. 문서 4종 세트 (단일 진실원)

| 파일 | 역할 | 갱신 시점 |
|------|------|-----------|
| `.claude/BACKLOG.md` | 다음 작업 우선순위 (P0/P1/P2) | 항목 추가/완료 시 즉시 |
| `.claude/PROGRESS.md` | 완료 이력 + 현재 git 상태 + 다음 세션 진입점 | 작업 종료 시 |
| `.claude/RETROSPECTIVE.md` | 실패/사고 + 재발 방지 규칙 + 반영 위치 | 실패 발생 시 |
| `.claude/plans/YYYY-MM-DD-{slug}.md` | 작업별 계획 + 결과 | 작업 시작 직전 / 완료 후 |

**갱신 의무 (CLAUDE.md "개발 워크플로우" 4단계에 박힘)**:
- BACKLOG에서 항목 제거 → 같은 작업 흐름에서 PROGRESS "완료된 작업"에 한 줄 추가
- 다음 작업 목록은 BACKLOG에만 기록, PROGRESS는 참조만 (drift 차단)
- 실패/허비 발생 시 RETROSPECTIVE에 회고 + 재발 방지 규칙 위치 명시

---

## 7. 사용자 운영 체크리스트

### 새 세션 시작 시
- [ ] `.claude/PROGRESS.md` "다음 세션 진입점" 확인 (`git status`도 함께)
- [ ] `.claude/BACKLOG.md` P0 항목 확인 → 다음 작업 결정

### 자동화 명령 내리기 전
- [ ] BACKLOG 우선순위가 정렬되어 있는가 (P0가 진짜 최우선?)
- [ ] 작업 규모가 1 PR로 들어갈만 한가 (Phase 분할 필요 없는지)
- [ ] 외부 의존성/설계 결정이 필요한 작업이 섞여 있지 않은가

### 위임 모드 진행 중
- 중간 보고는 사이클 1~2줄 요약만 (PR 번호, 커밋명)
- 멈춤 조건 도달 → 사용자에게 의사결정 요청 → 답변 후 재개
- 작업 끊고 싶으면 "그만" / "중단" / 새 메시지로 다른 작업

### 위임 모드 종료 후
- [ ] 최종 보고 확인 (PR 번호 목록, 머지 SHA)
- [ ] `.claude/RETROSPECTIVE.md` 회고 추가됐는지 확인 (실패 케이스 있었으면)
- [ ] `.claude/BACKLOG.md` 다음 우선순위 정렬 (다음 사이클 준비)

## 8. 사용자 자주 묻는 질문

**Q. 위임 모드 도중 사용자가 잠깐 자리 비웠는데 큰 결정 시점에 멈춤. 어떻게 처리?**
A. 그대로 멈춰 있음. 돌아와서 `AskUserQuestion` 답변하면 그 자리에서 재개. 응답 컨텍스트가 살아 있어 처음부터 다시 안 함.

**Q. 위임 모드에서 PR 5개가 자동 머지됐는데 한 개를 되돌리고 싶다.**
A. `gh pr` 명령으로 revert PR 생성. main 보호 룰은 PR 경로만 강제 — revert도 PR로 동일 흐름. ADR-011 v2의 SHA 검증 안전망이 의도와 다른 머지를 차단하는 게 1차 보호, revert는 사고 후 복구.

**Q. 매번 같은 명령을 외워야 하나?**
A. 아니. 자연어로 의도 전달하면 진입 키워드 매핑됨. "오늘 알아서 끝까지" / "남은 거 다 처리해줘" / "P1까지 해줘" 등 표현은 모두 위임 모드로 인식.

**Q. 자동화 사이클이 실패한 적 있나?**
A. 있음. `.claude/RETROSPECTIVE.md` 참조:
- PR #19 push 누락 사고 → 6단계 push 검증 가드레일
- PROGRESS stale로 새 세션 혼선 → 4단계 의무화
- 활성 PR 중 develop 추가 push → 7단계 SHA 검증 안전망
각각 재발 방지 규칙이 코드/규칙에 박혀 있어 같은 실패 재발 안 함.

**Q. 한 사이클이 너무 길어져 응답이 잘리지 않을까?**
A. 위임 모드 중간 보고는 1~2줄로 압축됨. 한 응답 안에서 PR 5~6개까지는 무리 없이 처리 가능. 그 이상이면 자연히 멈춤 조건(BACKLOG 빔, 큰 결정 등)에 걸려 정지.

## 9. 트러블슈팅

| 증상 | 원인 | 대응 |
|------|------|------|
| 자동화 명령했는데 매 단계 묻는다 | 기본 모드로 떨어짐 | "자율로 진행" / "위임 모드로" 명시 |
| SHA 검증에서 머지 차단됨 | PR 생성 후 develop에 추가 push 누적 | PR 본문 갱신 `gh pr edit --body` 후 재머지 시도, 또는 PR 닫고 새로 생성 |
| `gh pr merge` 거부됨 | `settings.local.json` `deny`에 등록됨 (ADR-011 v1 잔재라면) | 현재 v2부터 허용. settings 확인해서 `gh pr merge:*` deny 라인 있으면 제거 |
| 위임 모드 중간에 BACKLOG 항목이 추가됨 | 사용자 의도 외 작업이 발견됨 | AI가 새 항목을 BACKLOG에 적고 진행 (작업 끝에 보고) |
| Plan 모드 진입했는데 자동 안 됨 | Plan 모드는 ExitPlanMode 후 자동 모드 결정 | ExitPlanMode에서 자율/위임 모드 명시 |

## 10. 핵심 명령 치트시트

```
# 단발 자동 실행
"BACKLOG 다음 작업 진행해줘"          → 자율 모드 1 사이클

# 다발 자동 실행
"BACKLOG P0 다 자동 진행"              → 위임 모드, P0 비울 때까지
"BACKLOG P1까지 자동 진행"             → 위임 모드, P0 + P1
"오늘 알아서 끝까지"                    → 위임 모드, 전체

# 검증
"git fetch 실측해줘"                    → 외부 상태 검증
".claude/PROGRESS.md 진입점 보여줘"     → 다음 세션 시작점

# 강제 중단
"중단" / "그만" / 새 메시지로 다른 주제 → 위임 모드 정지
```
